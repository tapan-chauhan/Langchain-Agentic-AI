# Messages in LangChain

## Why Messages Matter
- Every agentic framework (LangChain, LangGraph, etc.) relies heavily on **messages** for communication.
- Messages carry an **identity** — who sent it and who received it — just like a conversation between two people.

## Real-World Analogy
Imagine two people talking — Rahul and Simon:
- **Rahul's message** → what Rahul says
- **Simon's message** → what Simon replies

Now replace Simon with an AI:
- **Rahul's message** → becomes a **User Message** (Rahul is the user)
- **AI's message** → becomes an **AI Message** (generated by the LLM)

## The Three Core Message Types

| Message Type | Who Controls It | Purpose |
|---|---|---|
| **HumanMessage** (User Message) | The user | What you send/ask the LLM |
| **AIMessage** | The AI/LLM | The model's generated response |
| **SystemMessage** | The developer | Sets the *tone*/behavior/environment for the LLM |

### System Message — Setting the Tone
- Analogy: telling Simon *"talk nicely and be a little polite"* before he talks to Rahul — this shapes all of Simon's future responses.
- Same idea applies to LLMs: you can instruct it to behave a certain way (formal, polite, funny, etc.) via a system message.
- Example use cases:
  - Writing an email to a friend → casual/polite tone
  - Writing an email to a manager → formal tone
  - Acting like a "Gen Z assistant" → fun, emoji-filled responses
- **Note:** System/Human/AI message format is essentially **OpenAI-style**. Other model providers may use different structures — this is one reason LangChain provides a unified **prompts** abstraction (to be covered next).

## Code: Using Messages in LangChain

### Install Required Library
```bash
uv add langchain-core
```

### Import Message Classes
```python
from langchain_core.messages import HumanMessage, SystemMessage, AIMessage
```

### Build a Message List
```python
my_messages = [
    SystemMessage(content="You are a Gen Z assistant who always answers in a fun way."),
    HumanMessage(content="bro tell me a fun fact")
]
```

### Invoke the Model with Messages
```python
response = llm_openai.invoke(my_messages)
print(response.content)
```
- Output tone changes based on the system message (e.g., fun, emoji-filled "Gen Z" style response instead of a plain/neutral one).

## Loading Environment Variables (API Keys)

Some smart code editors (e.g. Antigravity) may auto-load `.env` variables. But best practice is to load them explicitly:

```bash
uv add python-dotenv
```

```python
import os
from dotenv import load_dotenv

load_dotenv()  # loads all variables from .env into the environment
```

### Verify the API Key Is Loaded
```python
if os.environ.get("OPENAI_API_KEY"):
    print("bro API key variable exists")
```

## Key Takeaways
- Messages give structure and identity to LLM conversations: **who said what**.
- `HumanMessage` = your input, `AIMessage` = model's output, `SystemMessage` = tone/behavior you set.
- System messages let you steer the model's personality/style for a task (formal, casual, funny, expert, etc.).
- Always explicitly load environment variables with `load_dotenv()` for reliability across editors/environments.
- LangChain's System/Human/AI message format mirrors OpenAI's style; LangChain's **prompts** module exists to abstract this across different providers.
